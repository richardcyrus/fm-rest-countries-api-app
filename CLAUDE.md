# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A Frontend Mentor solution ("REST Countries API with color theme switcher") built with React 19, TanStack Start (full SSR, deployed on Vercel via Nitro), Vite+ (Vite 8 / Vitest 5), and TypeScript. The browser never calls the countries API: server functions hold a Bearer token and the full country list (see `docs/adr/0001-server-held-country-cache.md`). Domain vocabulary is in `GLOSSARY.md`.

## Commands

Toolchain is Vite+ (`vp`), with pnpm as the package manager (see `pnpm-workspace.yaml`, which pins `vite`/`vitest`/`vite-plus` via a catalog). The `package.json` scripts wrap `vp`:

- `pnpm dev` / `pnpm preview` — Vite dev server / preview of the production build. The server needs `COUNTRIES_API_TOKEN` (see `.env.example`); to develop offline run `node test/fake-upstream/main.ts` and set `COUNTRIES_API_URL=http://localhost:4010/countries/v5` with `COUNTRIES_API_TOKEN=test-token`
- `pnpm dev:live` — dev server with the real key injected from 1Password (`op run --env-file=.env.op`; reference `op://dev/rest_countries_api/credential`). `.env.op` holds only the reference, never a secret
- `pnpm test:live` — live contract test (`test/live-contract.test.ts`) against the real v5 API, also via 1Password; skipped by `pnpm test` unless `LIVE_API=1`
- `pnpm e2e` — builds, then runs the Playwright suite against the production build and fake upstreams (it starts them itself). Running `playwright test` directly reuses the last build, so rebuild first if `src/` changed
- `pnpm build` — typecheck (`tsc -b`) then `vp build`
- `pnpm lint` / `pnpm fix` — Oxlint check / autofix (config in `.oxlintrc.json`)
- `pnpm format` — Oxfmt (config is the `fmt` block in `vite.config.ts`)
- `vp check` — format + lint + type check in one pass; also runs on staged files via the `.vite-hooks/pre-commit` hook
- `pnpm test` — run the full Vitest 5 suite once (`vp test run`)
- `pnpm test:watch` / `pnpm test:coverage` — watch mode / coverage (no coverage provider is installed yet)

Run a single test file: `pnpm vp test run src/components/ThemeToggle.test.tsx`
Run a single test by name: `pnpm vp test run -t "renders correctly"`

Note `vp test` runs the built-in Vitest, while `vpr test` / `vp run test` runs the `test` script.

## Architecture

**Routing/entry**: TanStack Start file routes in `src/routes/`: `__root.tsx` (HTML shell, header, error and not-found UI, theme from the root loader), `index.tsx` (`/`, Home) and `details.$code.tsx` (`/details/:code`). `src/router.tsx` creates a `QueryClient` per router and wires the SSR query integration. `src/routeTree.gen.ts` is generated by the Start plugin (committed, excluded from lint/format); a fresh checkout needs `vp build` or `pnpm dev` once before `tsc -b` passes.

**Server modules** (`src/server/countries/`, framework-agnostic, unit-tested):

- `schema.ts` — zod schemas; the only place the upstream v5 contract is translated into the app's `Country`.
- `upstream.ts` — fetches every page with the Bearer token; errors expose only the status code. The real API (254 objects) lists 4 de facto states (Abkhazia, Northern Cyprus, Somaliland, South Ossetia) with an empty alpha-3 code; `hasAlpha3Code` drops them since a Country is identified by that code.
- `cache.ts` / `service.ts` — one in-process cache (24h TTL, stale-on-error, 60s retry backoff) and the questions asked of it: `search`, `regions`, `detail`, `borderCountries`.
- `query.ts` / `view.ts` — filtering, name sorting, cursor paging, and the display-ready shapes (population pre-formatted, lists flattened to strings).
- `config.ts` — validates `COUNTRIES_API_TOKEN`, `COUNTRIES_API_URL`, `COUNTRIES_CACHE_TTL_SECONDS`. `instance.ts` builds the process-wide service. `functions.ts` exposes it as `createServerFn` functions and replaces any failure with a generic message.

**Data flow**: route loaders call `ensureQueryData` / `ensureInfiniteQueryData` with the options in `src/queries/countries.ts` (which wrap the server functions), so the first page is server-rendered and handed to the client. Home uses `useSuspenseInfiniteQuery` with an `IntersectionObserver` sentinel; search (`q`) and region (a slug) live in zod-validated URL search params (`src/utils/homeSearch.ts`), and the search box is debounced (500ms) before it navigates. Details gets the Country Detail and its Border Countries in one call; an unknown code throws `notFound()`.

**Theming**: the `theme` cookie is read by `getTheme` in the root loader, which renders `<body class="dark">` on the server; `Header.tsx` toggles the class immediately and persists with the `setTheme` server function. CSS in `src/styles/global.css` keys off the `dark` class.

**Path alias**: `~/*` → `src/*`, configured in `tsconfig.app.json` and mirrored for Vite via `resolve.tsconfigPaths`. Use `~/...` imports in `src/` UI code; the `src/server/countries` modules use relative imports so `test/` (typechecked by `tsconfig.node.json`) can import them.

**UI primitives**: Radix UI (`radix-ui` package, e.g. `Select`, `VisuallyHidden`) for accessible interactive components, Heroicons for icons. Styling is plain CSS (native nesting, no preprocessor) with CSS custom properties (no CSS-in-JS, no Tailwind) — component files import no stylesheets directly except `Loading` (CSS module); everything else relies on global class names from `src/styles/global.css`, imported once in `__root.tsx`.

## Deployment (Vercel)

Nitro emits a Vercel Build Output (`.vercel/output`, a `nodejs24.x` function) whenever `VERCEL=1` is set, so `VERCEL=1 pnpm build` previews exactly what Vercel produces. There is no `vercel.json`. In the Vercel project: set `COUNTRIES_API_TOKEN` for Production and Preview (nothing validates it at startup; without it every page shows the "temporarily unavailable" error), use Framework Preset "TanStack Start" or "Other" with Build Command `pnpm build`, and Node.js 24.x (`engines.node` is `24.x`). Vercel installs with pnpm 9 or 10 (from `lockfileVersion: 9.0`), not the pnpm 12 in `devEngines`; the project is verified to install with pnpm 10 using `--frozen-lockfile`. Production security headers come from the explicit route in `vite.config.ts` (`SECURITY_HEADER_ROUTES`); it needs `continue: true`, and Nitro's `routeRules` headers do not set that, so do not use them here. Each cold function instance refills its country cache (about 3 upstream calls) and the API allows 20 requests per 10 seconds.

## Testing

- **Unit tests** (`src/**/*.test.ts(x)`, `pnpm test`): pure logic for the server modules, search-param and theme parsing, `useDebounce`, and `ThemeToggle`. The Start and Nitro Vite plugins are disabled under Vitest (`process.env.VITEST` in `vite.config.ts`) because they break Vitest's node environment.
- **Integration test** (`test/service.test.ts`): exercises the upstream client and service against the **fake upstream**.
- **Fake upstream** (`test/fake-upstream/`, fixture `test/fixtures/countries.v5.json`): a plain `node:http` server imitating the v5 API (Bearer auth, `limit`/`offset`, `data.objects`/`data.meta`). `startFakeUpstream()` is used in-process by Vitest; `main.ts` runs it standalone for Playwright. It honours `response_fields` and `limit`/`offset`. `test/fixtures/countries.v5.json` is a snapshot of the real v5 response and is **git-ignored: the API terms do not allow redistributing it**. Generate it locally with `pnpm fixtures:refresh` (needs the 1Password key) before running unit or e2e tests; they fail with a message saying so if it is missing. `test/fixtures/sample-canada.v5.json` is the single sample object the API returns for its public demo key. `pnpm test:live` checks the fake's field types and meta keys against the real API, so rerun it after changing the fake, the fixture, or `RESPONSE_FIELDS`.
- **End-to-end** (`e2e/`, `pnpm e2e`): Playwright against `pnpm build` output. `playwright.config.ts` starts three app instances, each with its own fake upstream (ports in `e2e/servers.ts`): _healthy_ (most specs), _failing_ (the upstream answers 500 from the start), and _flaky_ (1s cache TTL, driven over HTTP through the fake's `/__control/fail?status=`, `/__control/reset`, and `/__control/requests` routes). Specs: `smoke`, `browse` (region filter, search, infinite scroll), `details`, `theme`, `resilience` (error page, retry, stale-on-error), `security` (the browser never calls the upstream; the token never reaches a page, script, or server-function response). The `flaky` app is never reused between runs so its cache starts empty.

Component tests use `@testing-library/react` (`render`, `screen`, `fireEvent`). Import test APIs (`describe`, `it`, `vi`, etc.) from `vite-plus/test`, not `vitest`, and Vite APIs from `vite-plus`. Mock call history is cleared between tests (Vitest 5 default), so create mocks per test.
